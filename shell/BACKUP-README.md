# System Backup: `etc-minimal.tgz` + `lists_tar.xz`

Generated by `make-system-backup.sh` on a Fedora (dnf/rpm-based) Linux system.

This is a **config + inventory backup**, not a full system image. It is
designed to be paired with a **fresh OS reinstall**: you install a clean
Fedora, then use these two archives to quickly get repos, packages, and
system config back to how they were — rather than restoring a byte-for-byte
copy of the old root filesystem.

---

## 1. What's in each archive

### `etc-minimal.tgz` — curated copy of `/etc` (+ a bit of `/var/lib`)

| Area | Paths | Notes |
|---|---|---|
| Package repos | `etc/yum.repos.d/`, `etc/dnf/` | RPM Fusion, COPR repos, VS Code repo, etc. |
| Networking | `etc/NetworkManager/system-connections/`, `etc/NetworkManager/conf.d/`, `etc/hosts`, `etc/hostname`, `etc/wireguard/`, `etc/openvpn/` | **Wi-Fi passwords live here** |
| Boot / disk | `etc/fstab`, `etc/crypttab`, `etc/default/grub`, `etc/grub.d/` | Tied to old disk UUIDs — see warnings |
| Kernel / modules | `etc/modprobe.d/`, `etc/dracut.conf.d/`, `etc/modules-load.d/`, `etc/sysctl.d/` | Blacklists, custom sysctls |
| Display | `etc/X11/xorg.conf.d/` | Custom X11 quirks (keyboard layout, etc.) |
| Service defaults | `etc/sysconfig/` | crond, firewalld, samba, sshd, kdump, etc. env files |
| SSH | `etc/ssh/` (config only) | **Host keys excluded on purpose** — see below |
| Firewall | `etc/firewalld/` | Zones, policies |
| Printing / sharing | `etc/cups/`, `etc/samba/` | |
| Certificates / trust | `etc/pki/` | System CA trust store, RPM GPG keys, akmods signing keys |
| Locale / env | `etc/locale.conf`, `etc/vconsole.conf`, `etc/environment`, `etc/profile.d/` | |
| Auth / access | `etc/pam.d/`, `etc/security/limits.d/`, `etc/polkit-1/`, `etc/selinux/config`, `etc/sudoers`, `etc/sudoers.d/` | |
| Accounts | `etc/passwd`, `etc/group`, `etc/shadow`, `etc/gshadow`, `etc/subuid`, `etc/subgid` | **Contains password hashes** — see below |
| systemd | `etc/systemd/system/`, `etc/systemd/user/` | Includes the `*.wants/` symlinks that show which services were enabled |
| udev | `etc/udev/rules.d/` | Custom device rules |
| Misc `/var/lib` | `var/lib/bluetooth/`, `var/lib/AccountsService/` | Bluetooth pairings, user account icon |

**Deliberately excluded:**
- `etc/ssh/ssh_host_*` — SSH host identity keys. These are meant to be
  unique per machine/install; reusing them defeats their purpose and can
  trip SSH's "host key changed!" warning on clients that expect the *old*
  identity to disappear.
- Anything not listed above — this is *not* a full `/etc` copy. Machine-ID
  files, caches, runtime state, and anything version-specific to the old
  install are left out on purpose.

### `lists_tar.xz` — plain-text inventories

All files live under `lists/` inside the archive.

| File | Contents |
|---|---|
| `dnf-installed.txt` | Every installed package (name only) |
| `dnf-userinstalled.txt` | Packages **you** explicitly asked for (excludes pure dependencies) — the one to use for reinstalling |
| `dnf-groups.txt` | Installed dnf package groups |
| `dnf-enabled-repos.txt` | Currently enabled repos |
| `dnf-repos-all.txt` | All configured repos (enabled + disabled) |
| `rpm-all.txt` | Full `rpm -qa` output with versions (reference only, don't reinstall exact versions) |
| `flatpak-apps.txt` | Installed Flatpak application IDs |
| `flatpak-refs.txt` | Flatpak refs (id/branch) |
| `flatpak-apps.tsv` | Flatpak apps with name, version, branch, origin |
| `flatpak-runtimes.tsv` | Installed Flatpak runtimes |
| `flatpak-remotes.txt` | Configured Flatpak remotes (e.g. Flathub) |
| `vscode-extensions.txt` | VS Code extension IDs |
| `dconf.ini` | Full GNOME/dconf settings dump for your user |
| `desktop-files.txt` | Installed `.desktop` launcher files (system + user) |
| `usr-local-bin.txt` | Listing of `/usr/local/bin` |
| `local-bin.txt` | Listing of `~/.local/bin` |
| `opt.txt` | Listing of `/opt` |
| `lsblk.txt` | Block devices, filesystems, UUIDs |
| `fdisk.txt` | Partition tables |
| `df.txt` | Filesystem usage at backup time |
| `mount.txt` | Active mounts at backup time |
| `swapon.txt` | Active swap at backup time |
| `lspci.txt` | PCI devices + kernel drivers in use |
| `lsusb.txt` | USB devices |
| `lscpu.txt` | CPU info |
| `dmidecode.txt` | Motherboard/BIOS/system info |
| `nvidia-smi.txt` | NVIDIA GPU + driver status (if applicable) |
| `mok-enrolled.txt` | Enrolled Secure Boot MOK keys (if applicable) |
| `sestatus.txt` | SELinux mode |
| `timedatectl.txt` | Timezone / NTP config |
| `localectl.txt` | System locale / keyboard layout |
| `nmcli-connections.txt` | NetworkManager connection summary |

## 2. What is **NOT** backed up

This is the important part. These archives cover system configuration and
inventories only.

- ❌ **`/home`** — your documents, downloads, pictures, projects, everything.
- ❌ **Dotfiles / app data** — `~/.bashrc`, `~/.config`, `~/.mozilla`,
  `~/.ssh` (your personal SSH keys!), browser profiles, game saves, etc.
- ❌ **Actual installed software** — only *lists of package names* are
  saved. You reinstall the packages fresh from repos, you don't restore
  binaries from this backup.
- ❌ Containers/VMs (Docker images, libvirt disks, Waydroid data).
- ❌ Anything outside `/etc` and the couple of `/var/lib` paths listed above
  (e.g. `/var/lib/docker`, `/var/lib/libvirt`, `/var/log`, databases).
- ❌ SSH host keys (excluded intentionally, see above).

**Back these up separately** (e.g. with `rsync`, `restic`, `borg`, or a
cloud sync) before reinstalling.

## 3. Sensitive contents — handle with care

These archives contain real secrets and identifiers. Treat them like you
would a password manager export:

- **`etc/shadow`, `etc/gshadow`** — password hashes for every local account.
- **`etc/NetworkManager/system-connections/*.nmconnection`** — saved Wi-Fi
  and VPN passwords in recoverable form.
- **`etc/pki/akmods/private/*.priv`** — a local module-signing private key
  (used for Secure Boot + out-of-tree kernel modules like NVIDIA/VirtualBox).
- **`etc/openvpn/`, `etc/wireguard/`** — VPN configs/keys, if present.

Don't upload these archives to a public place. A local encrypted drive or
a private, encrypted cloud location is appropriate.

## 4. How to restore after a fresh reinstall

Assume you've just done a clean install of the **same Fedora version** and
are logged in as your user with sudo access.

### Step 1 — Extract the archives somewhere readable
```bash
mkdir -p ~/restore
tar xzf etc-minimal.tgz -C ~/restore
tar xJf lists_tar.xz -C ~/restore
```

### Step 2 — Re-add your package repos
```bash
sudo cp ~/restore/etc/yum.repos.d/*.repo /etc/yum.repos.d/
sudo dnf clean all
sudo dnf makecache
```
You'll likely be prompted to import GPG keys for RPM Fusion / COPR / VS Code
etc. the first time you install from them — that's normal.

### Step 3 — Reinstall your packages
```bash
sudo dnf install $(cat ~/restore/lists/dnf-userinstalled.txt)
```
This reinstalls the packages you explicitly chose, and lets dnf resolve
fresh, version-appropriate dependencies rather than forcing old versions.
Don't try to replay `rpm-all.txt` verbatim — it's a point-in-time reference,
not an install list.

### Step 4 — Reinstall Flatpaks
```bash
# Re-add remotes first (usually just Flathub)
cat ~/restore/lists/flatpak-remotes.txt

flatpak remote-add --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo

# Then install each app
while read -r app; do
  flatpak install -y flathub "$app"
done < ~/restore/lists/flatpak-apps.txt
```

### Step 5 — Restore Wi-Fi / VPN connections
```bash
sudo cp ~/restore/etc/NetworkManager/system-connections/*.nmconnection \
        /etc/NetworkManager/system-connections/
sudo chmod 600 /etc/NetworkManager/system-connections/*.nmconnection
sudo chown root:root /etc/NetworkManager/system-connections/*.nmconnection
sudo systemctl restart NetworkManager
```

### Step 6 — Selectively restore config (don't overwrite blindly)
Compare and hand-copy what you actually want, e.g.:
```bash
sudo cp -r ~/restore/etc/firewalld/zones/*.xml   /etc/firewalld/zones/
sudo cp    ~/restore/etc/samba/smb.conf          /etc/samba/smb.conf
sudo cp -r ~/restore/etc/modprobe.d/*.conf       /etc/modprobe.d/
sudo cp -r ~/restore/etc/sysctl.d/*.conf         /etc/sysctl.d/
sudo cp -r ~/restore/etc/X11/xorg.conf.d/*       /etc/X11/xorg.conf.d/
```

**Do NOT blindly copy over these — they're either auto-generated fresh or
tied to the old machine:**
- `etc/fstab`, `etc/crypttab` — reference the *old* disk's UUIDs. Compare
  against the new `/etc/fstab` and merge manually (extra mount points,
  custom options) instead of overwriting.
- `etc/passwd`, `etc/shadow`, `etc/group`, `etc/gshadow` — your new install
  already created your user with a new UID/GID mapping; overwriting these
  can break login. If you need your *old password hash* for a specific
  account, copy just that one line by hand.
- `etc/ssh/sshd_config` / `ssh_config` — fine to compare and merge, but
  never copy host keys back (there aren't any in this backup anyway).
- `etc/pki/` — the fresh install already has an up-to-date CA trust store;
  only pull in anything custom you added under
  `etc/pki/ca-trust/source/anchors/`.

### Step 7 — Re-enable services
```bash
ls ~/restore/etc/systemd/system/multi-user.target.wants/
ls ~/restore/etc/systemd/system/graphical.target.wants/
```
For anything non-default you had running (Docker, RustDesk, Waydroid, a VPN
split-tunnel service, etc.):
```bash
sudo systemctl enable --now docker
sudo systemctl enable --now rustdesk
```

### Step 8 — Restore GNOME/dconf settings and VS Code extensions
```bash
dconf load / < ~/restore/lists/dconf.ini

while read -r ext; do
  code --install-extension "$ext"
done < ~/restore/lists/vscode-extensions.txt
```

### Step 9 — Restore `/home` and personal data
This backup doesn't cover it — restore from whatever separate backup
(external drive, cloud, `rsync`/`restic`/`borg` snapshot) you made of
`/home` before reinstalling.

### Step 10 — Sanity check with the hardware lists
Use `lspci.txt`, `lsusb.txt`, `nvidia-smi.txt`, and `mok-enrolled.txt` as a
checklist to confirm all your hardware is detected and drivers (especially
proprietary NVIDIA, if used) are working the same as before.

## 5. Re-running the backup

The generating script (`make-system-backup.sh`) is idempotent and safe to
re-run any time:

```bash
sudo ./make-system-backup.sh [optional-output-directory]
```

- Must be run with `sudo` (needs root to read `/etc/shadow`, NM secrets,
  etc.).
- Defaults to writing into `~/system-backup-<timestamp>/` for whichever
  user invoked `sudo`.
- The two output archives are `chown`ed back to that user and set to mode
  `644`, so **no sudo is needed afterwards** to copy, move, or upload them.
  (Note: files *inside* `etc-minimal.tgz`, like `/etc/shadow`, keep their
  original restrictive permissions once extracted — only the archive file
  itself is made freely readable.)
- Missing tools (e.g. no `nvidia-smi` on a non-NVIDIA machine) are skipped
  gracefully with a note in the corresponding list file — the script won't
  abort.

## 6. Quick reference: what to trust after a reinstall

| Question | Answer |
|---|---|
| "What packages did I have installed?" | `lists/dnf-userinstalled.txt` |
| "What Flatpaks did I have?" | `lists/flatpak-apps.txt` |
| "What repos was I using?" | `lists/dnf-enabled-repos.txt`, `etc/yum.repos.d/` |
| "What was my Wi-Fi password again?" | `etc/NetworkManager/system-connections/*.nmconnection` |
| "What GNOME settings did I have?" | `lists/dconf.ini` |
| "What services did I have enabled?" | `etc/systemd/system/*.target.wants/` |
| "What GPU/driver was I running?" | `lists/lspci.txt`, `lists/nvidia-smi.txt` |
| "Did I have Secure Boot MOK keys enrolled?" | `lists/mok-enrolled.txt` |
| "Where are my files?!" | Not here — that's `/home`, back it up separately. |
